个人网站的死亡原因，排名第一的不是没人看，是**维护成本**。

租一台服务器，你签下的是一份长期合约：续费、系统补丁、TLS 证书到期、SSH 端口每天被扫几百次、某天发现 CPU 跑满在帮别人挖矿。这些事每一件都不难，但它们会持续消耗你的注意力。而注意力是有限的，投入产出比最低的那件事，总是最先被放弃。

所以真正的目标不是"便宜"，而是**零维护**。

## 静态站点的三个数

一个个人站需要的能力其实很少：

1. 展示页面和文章
2. 支持自定义域名和 HTTPS
3. 更新时不折腾

这三件事，静态托管全都免费且自动：

| 需求 | 传统服务器 | 静态托管 |
| --- | --- | --- |
| 页面服务 | 自己配 Nginx | 免费 |
| TLS 证书 | Certbot + 定时任务 | 自动签发续期 |
| 全球加速 | 自己上 CDN | 自带边缘网络 |
| 系统维护 | 你自己 | 不存在 |
| 月成本 | 几十到几百 | 0 |

## 架构长什么样

```
本地写 Markdown
      ↓
   git push
      ↓
平台自动构建（Astro → 纯 HTML）
      ↓
全球边缘节点分发
```

构建在平台上跑，产物是一堆 HTML 和 CSS。没有进程常驻，没有数据库连接池，没有会话状态。请求进来，文件出去。

这种架构的另一个好处是**几乎不可能被打挂**。静态文件没有查询、没有序列化、没有可注入的输入面。攻击面上只剩一个域名解析。

## 真正的代价

公平地说，代价是有的，而且要提前想清楚：

**不能用服务端能力。** 想要登录、评论、表单提交、实时数据，静态站给不了。这些需求要么找第三方的托管服务补，要么说明你需要的其实不是静态站。

**构建时间随内容增长。** 几百篇文章以内都是秒级，上万篇才需要考虑增量构建。

**平台锁定。** 缓解办法是保持产物是纯静态文件 —— 任何能托管静态文件的平台都能接。换平台等于改一个配置文件。

## 我的选择

这个站用 Astro，输出纯静态，托管在边缘网络上。域名之外没有第二笔支出。

写一篇文章的流程是：新建一个 `.md` 文件，写完 `git push`。三十秒后线上可见，然后我关掉电脑去干别的。

这就是全部。没有需要维护的东西 —— 这正是它能在三年后还活着的原因。
